# society — 用真实数据造人口，模拟 GTM 方案的反馈

> 状态：设计中，尚未实现。**先做校准，再决定是否投入。**

sv-gtm-advisor 回答的是「别人做过什么、什么被验证过」。
这个目录要回答的是另一个问题：**「我这套 messaging 发给不同人群，会被怎么理解、谁会无感、哪里有风险」。**

## 为什么需要自己造人口

[MiroFish](https://github.com/666ghj/MiroFish)（盛大孵化，仿真引擎是 CAMEL-AI 的 OASIS）的做法是：
从种子材料里抽实体建知识图谱 → 每个实体生成一个社交账号 → 跑 Twitter / Reddit 双平台模拟。

读过它的 `oasis_profile_generator.py` 后确认两件事：

1. **没有预置人口**。agent 数量等于材料里抽出的实体数，不会合成背景人群。
   给它三套 messaging 文案，它抽不出人来。
2. **动作空间只有六个**：发帖、点赞、转发、引用、关注、什么都不做。
   所以它模拟的是「信息在社交网络里怎么扩散」，不是「谁会掏钱」。

结论：人口要我们自己建。而且**人口是一次性资产、可复用**——每次 launch 都用同一批人，
方案之间才可比，校准数据才能累积。这和 MiroFish 每个话题重新抽实体是完全不同的思路。

## 分 segment 建，不要混在一起

每个 segment 的**抽样框**和**校准数据**都不同，所以是几套独立人口，共用同一套 schema 和验证脚本。

| 人口 | 决策单位 | 适合的引擎 | 抽样框来源 | 语音来源 |
|---|---|---|---|---|
| **全球开发者** | 个人 | 社交扩散（OASIS） | `crustdata_v3_person_search` 按 title / skills / 地区 | `hackernews_search`、`twitterapi_advanced_search` |
| **SMB 买家** | 1–2 人拍板 | 简化委员会 | `peopledatalabs_company_search` 按规模 / 行业 | HN、X、G2 类评论 |
| **Enterprise 买家** | 5–7 人采购委员会 | **顺序过关卡，不是社交模拟** | 真实公司 + 真实职位构建委员会 | 同上 + `bloomberry` 技术栈变动 |
| **消费者** | 个人 | 社交扩散 | 待定 | 平台评论 |

**企业侧为什么不用社交模拟**：真实采购里没人靠转发做决定。要模拟的是
「使用者想用 → 技术能接 → 安全放行 → 采购批预算」这几道关卡，卡在哪一关，
就是 messaging 该补哪一块。这个模型比社交模拟简单，但对 B2B 更有用。

## 「基于事实」的三层锚定

人口不能是想出来的。三层都要挂在真实数据上：

1. **结构比例**：从真人库按条件统计真实分布（国家、职级、技能、公司规模），
   按配额分层抽样。不是凭感觉编比例。
2. **个体语音**：每个 persona 绑定几段**真人写的原文**（HN 评论、X 发言、产品评论），
   保留出处以便追溯。他的词汇、顾虑、价格敏感度都来自真人，不是模型的刻板印象。
3. **网络结构**：少数枢纽 + 大量边缘节点，同国家 / 同职业更容易相连，跨群体桥梁很少。
   连接倾向也从真实讨论里提取（谁回复了谁）。
   **全连接必然收敛到共识，那个共识是模拟的产物，不是社会的预测。**

## 投入之前必须通过的三项体检

| 测什么 | 怎么测 | 不通过就止损 |
|---|---|---|
| **有没有判别力** | 用 Fletch PMM 上百对「改版前 / 改版后」文案去标签盲测，看能否复现「改版后更好」 | 接近随机 → 这套模拟对 messaging 没有判别力 |
| **是不是真异质** | 异质人口 vs 同质对照组（一个 persona 复制 N 份）的语义方差、意见分布熵 | 差不多 → 异质化是假的，反馈无意义 |
| **有没有区分度** | 三套方案的得分分布 | 挤在一起 → 分不出优劣，无法决策 |

Fletch 的 before/after 是我们独有的标准答案：现实世界已经判定改版后更好，
这让「模拟到底准不准」变成一个可以写进文档的数字，而不是感觉。

## 已知的能力边界

即使人口建得很好，它给的**不是转化率预测**，而是三件事：

- 哪套 messaging 会被误读，误读成什么
- 哪个群体完全无感（真实世界最大的一类反应是「没注意到」，模拟里必须显式保留这类行为）
- 跨文化风险：在美国很聪明的一句话，在日本或德国可能直接冒犯人

最终排序仍然要靠真实的小实验（落地页 A/B、冷邮件回复率、小额广告测试）。
**这里做的是淘汰，不是选优。**

## 目录规划（待实现）

```
society/
  panels/          人口定义与生成产物（按 segment 分）
  sampling/        配额采样器：真实分布 → 人口骨架
  voice/           语料绑定：真实发言 → persona，保留出处
  network/         网络生成：按真实连接倾向连边
  export/          导出 OASIS 格式（跳过 MiroFish 的抽实体步骤，直接喂人口）
  calibration/     三项体检
```

## 注意

- MiroFish 是 **AGPL-3.0**：内部用没问题，将来若做成对外服务，我们的改动也要开源。
- 抓取的真实发言用于构造 persona，**不外传、不入库**；只保留出处链接。
- 凭证一律走本地 `.env`，不进仓库。
