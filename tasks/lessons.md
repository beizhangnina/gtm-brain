# 经验教训（gtm-brain）

## 来自旧 dormy-brain 的教训（开工前已知，不要重犯）
- **ingest 脚本必须进 repo。** 旧的放在 `~/tmp/dormy-ingest/`，现在已经丢了。D-006 说的是「vault 数据不进 git」，不是「代码不进 git」。
- **`python -u` 是必须的。** 否则 stdout block-buffer 到 4KB 才 flush，长跑任务看不到进度。
- **长跑用 `nohup ... &`**，脱离 Terminal，关机重开能续。
- **进度写 jsonl，按 source_path 跳过已 ok 的**，网络抖动/重部署不会让整轮白跑。
- **Secret 单向流动**：签发方 → 1Password → 部署平台。不经过对话、不进 git。旧项目为此 rotate 了 5 次。
- **自己不用的服务会荒废。** 旧 dormy-brain 连阿蓓自己机器都没配，所以烂掉了。新的必须第一时间配到自己机器上。

## 2026-09-20 图片瘦身

- **数字对了不代表做对了。** 「压缩 24x、零失败」的基准报告看起来很漂亮，
  但底下藏着「整页截图被压成 152px 宽」这个会毁掉最有价值内容的 bug。
  **必须裁一块出来用眼睛看**，压缩比和失败数都发现不了它。
- **先看数据分布再定参数。** 一句 `thumbnail((1600,1600))` 看着人畜无害，
  是因为默认脑补「图片都是横的」。实际抽样 400 张才发现 5% 是 1:5 以上的长图。
- 库在持续增长：最大单图从 20MB（9/19 测）涨到 36.6MB（9/20 测）。
  所有全量数字都要当次实测，不要写死。
- **upsert 的 key 必须先证明唯一。** slug 撞车（9 篇同名的 "Taking the week off"）
  会让 put_page 静默覆盖，不报错、不失败。直觉上"标题总不会重复吧"是错的。
  同类检查应该成为任何 upsert 型写入的必做步骤。
- **验证手段本身也要验证。** 用 HEAD 查 Supabase 的 cache-control 得到的是假象，
  害我排查了 6 种 header 写法，实际原始实现一直是对的（见 G-003）。
- **API 返回"成功"不等于事情做成了。** gbrain 的 put_page 叠了三层假阳性：
  未知参数静默忽略、错误藏在 result.isError 里、写入本身是异步的。
  任何写入后都要回读验证，尤其是第一次对接一个新 API 时。
- **先读 schema 再传参。** 我按直觉猜了 body/title/tags，全错。
  `tools/list` 里就有完整 inputSchema，读一眼的成本远低于事后排查。
- **启动后要验证「在动」，不是「在跑」。** 重启 ingest 后我确认了进程存在就离开，
  实际它在启动阶段崩了、一篇没处理。正确的验证是等几分钟看计数器有没有增长。
- **重试要覆盖所有网络路径，不能只覆盖主循环。** 一次 token 超时崩掉整轮。

## 2026-09-22 全量 ingest 的停顿（G-013）

- **不要把「对方服务端的问题」当成终点。** 我连续几个小时汇报「Supabase 锁争用、只能等」，
  用户一问「为什么不自己 fix」，20 分钟就查到根因是我们自己的部署区域错了。
  规则：遇到反复出现的停顿/变慢，**第一次出现就追到根因**，不要等第三次。
  排查顺序：grep 报错原文进源码 → 采样 `pg_stat_activity` 看谁占锁 → 看占锁期间它在等什么。
- **部署后要核实实际状态，而不是信文档。** 文档写「Railway 新加坡区」，实际是 us-west2，
  而且这条错误信息还被我拿去解释了另一个现象（G-010 的 9s embedding）。一个没核实的前提，污染了后面两次归因。
- **估剩余时间前先想清楚瓶颈在哪。** 我按「文章长短」估了两次都错了，瓶颈其实是服务端串行加锁等待。
- **跳过逻辑的 key 要覆盖产出物的全部输入。** ingest 只看笔记源文件 sha，漏掉了「图后来才上传」
  这个输入，周更会永久留下死链（G-014）。只有真正把周更流程完整跑一遍才发现 ——
  **收尾时要按真实的周期性场景端到端跑一次**，不能只验证一次性的全量回填。
- **`set -u` 的 bash 里，变量后紧跟全角标点要写 `${var}`。** `$fail）` 会被当成变量名的一部分。
- **退出码要真的表达成败。** weekly-sync 的 `fail` 标记原来形同虚设：slim/upload/ingest 有失败也返回 0。
